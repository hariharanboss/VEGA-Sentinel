# firmware/ — VEGA ARIES v2.0 firmware

All sketches target **VEGA ARIES v2.0** (VEGA Processor: ARIES Boards → **ARIES v2**), Arduino IDE 1.8.19, VEGA core C-DAC v1.1.2, Serial Monitor 115200.

> ⚠️ Board is **ARIES v2.0** — not "ARIES IoT v2.0".

## Layout

| Folder | Sketches | Purpose |
|---|---|---|
| `board_tests/` | 01 hello_world · 02 rgb_led_test · 03 adc_test · 08 simple_demo | Board package, serial, onboard RGB LED (GPIO24=R, 22=G, 23=B, active-low), buttons, ADS1015 ADC — no external wiring needed |
| `sensor_tests/` | 04 mq2_raw_read · 05 dht22_test · 06 combined_acquisition | Per-sensor verification with pass criteria |
| `data_collection/` | 07_data_logger | CSV rows over serial for dataset building (use with `tools/data_logger/sentinel_logger.py`) |
| `sentinel_final/` | **sentinel_final** (full system) · **model_a_aries_test** (Model A math verification) | Deployment firmware + on-board model check |

## Bring-up order

1. `board_tests/01..03` (no wiring) → 08 (onboard demo)
2. `sensor_tests/04..06` (wire MQ-2 divider, then DHT22, then both)
3. `data_collection/07` + PC logger → collect datasets
4. `sentinel_final/model_a_aries_test` → verify the model math on-board
5. `sentinel_final/sentinel_final` → full system

## Pin assignments (final system)

| ARIES v2.0 pin | Connected to |
|---|---|
| GPIO0 | DHT22 DATA (3.3 V sensor) |
| GPIO1 | Flame sensor DO (active-LOW) |
| GPIO2 | 1 kΩ → 2N2222 base → buzzer driver |
| A0 | MQ-2 AO through 2×2.2 kΩ divider |

## Key verified facts baked into the sketches

- `analogRead()` uses the onboard ADS1015; effective single-ended readings ≈ **0–2047** in our tests. MQ-2 values are raw counts, not ppm.
- `pinMode()` on this core honours only INPUT/OUTPUT; `INPUT_PULLUP` is a no-op — DHT22 needs its external pull-up (present on the module/wiring).
- Flame module is **active-LOW** (LOW = flame detected).
- The buzzer is switched by a **2N2222** (GPIO sources only base current); never drive it directly from a GPIO (12 mA max).
- Onboard RGB LED is active-low: GPIO24=R, 22=G, 23=B; buttons read LOW when pressed.

## Final firmware behaviour (`sentinel_final/`)

- 2500 ms sampling; 10-sample sliding window (~22.5 s).
- **DHT-failure policy:** read sensors into temporaries → validate → only then shift window/insert/infer. On failure: sample discarded, window preserved, alarm state untouched.
- **Temporal confirmation:** 2 consecutive abnormal AI windows → buzzer ON; 3 consecutive normal windows → buzzer OFF.
- Serial CSV output (same as dataset format): `timestamp_ms,temp_c,humidity_pct,mq2_adc,flame_state,dht_ok`, plus `AI,p=...,status=...` decision lines.
- Model constants live in `sentinel_final/model.h` — auto-generated by `ml/deployment/export_model_to_cpp.py`; never hand-edit.
